# 本机浏览器采集验证 · 2026-10-14

用户选择先验证正常网页浏览器采集，而非等待官方应用审批。本次由浏览器操作工具读取当前已加载的页面，没有提取登录凭证、调用隐藏状态、改签名或绕过平台验证。

- 搜索方向：`vibe coding`，使用网站的“最新发布”排序。
- 第一页能取得至少 30 条视频卡片的标题、作品地址、作者名称、本人空间地址、页面显示的发布时间和时长。
- 作者空间中进入“投稿”，能读取“最新发布”视频列表；首页的收藏、点赞和推荐不能当作该作者自己的投稿。
- 进一步打开一条具体作品，可以读取精确的原始发布时间及作者简介文字。
- 实测样本：[表情包存了不少，想用却找不到，于是我做了个小工具 (Vibe Coding)](https://www.bilibili.com/video/BV1Cupy6sEa9/)，上传者泥巴窝管嘴，作品页显示 `2026-10-14 13:43:53`。作者投稿列表与搜索结果指向同一 BV 作品。

这证明正常网页是可进一步开发的采集路径。2026-10-15 已加入浏览器助手测试版及本地日报连接，但尚未安装与完成扩展真实运行验收，因此本次网页读取通过不等于定时采集已经部署完成。

作品页的“章节要点”标注“内容由AI生成”。它不是作者原文或完整字幕，助手不将其作为六字段观点的原文依据。

重新直接打开 B站投稿网址时曾出现投稿数量与空列表矛盾。助手使用正常主页到投稿的点击路径，未读到作品时暂停，不把失败解释为作者没有更新，也不覆盖历史资料。

## 后续实现的约束

1. 先读取正常显示的视频卡片和本人投稿，不把页面的相关推荐归属给当前作者。
2. 搜索页的“几小时前”“昨天”保留为页面时间标签；需读取作品页的可靠原始时间，不能把采集时刻冒充发布时间。
3. 同一作品按平台作品 ID 去重，保存首次发现时间；新发现与新发布分开。
4. 只得到标题、简介和作者资料时，保留为候选；未读取原文或字幕，不自动补出六字段观点。
5. 网站搜索结果中仍包含课程推广、搬运与题文不符内容。能读取结果不代表筛选质量满足用户偏好。
6. 测试版客户端已加入可恢复队列、去重、状态与日报连接，设置少量每日任务；需要浏览器正常运行，登录或验证失效时暂停。仍待扩展首次真实验收。
7. 当前界面明确标注测试版及未配对状态。一次网页测试或模拟队列通过不代表用户电脑已部署自动发现和追新。
