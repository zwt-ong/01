# 0.2 配置：自动发现与本地整理

先双击桌面的 **01**，或在项目目录双击 `start.cmd`。打开“信息源与设置”。博客候选采集不需要下面两项配置；陌生 YouTube 创作者发现需要密钥，自动观点整理需要已安装的本地模型。

## 一、免费 YouTube Data API 密钥

1. 打开 [Google Cloud 控制台](https://console.cloud.google.com/)，登录你自己的 Google 账号。
2. 点顶部项目选择器，选择“新建项目”。项目名称可以填 `01-radar`，创建后切换到它。
3. 打开 [YouTube Data API v3 页面](https://console.cloud.google.com/apis/library/youtube.googleapis.com)，确认选中了刚创建的项目，点“启用”。
4. 到“API 和服务”→“凭据”→“创建凭据”→“API 密钥”。本项目搜索公开内容，使用 API 密钥即可，不需要 OAuth 客户端或服务账号。
5. 编辑密钥，将“API 限制”设为仅允许 **YouTube Data API v3**。请求由本机 Python 服务发送，不能使用浏览器 HTTP Referer 限制；若你有固定公网 IP，可使用相应 IP 限制。避免启用无关付费服务。
6. 复制密钥，回到 **01 → 信息源与设置 → YouTube 自动发现**，粘贴进密码框，保存。密钥只写入被 Git 忽略的 `config.local.json`，页面状态只返回“已配置”，不返回密钥。
7. 点“更新日报”，更新完成后到“发现候选”查看。若显示搜索失败，检查所选项目、API 是否启用、密钥的 API 限制、配额和网络。配置密钥不能解决网络不可达。

**不要把密钥发到聊天、公开截图或 GitHub。** 更换密钥时填写新值；留空会保留现有密钥，“删除本地密钥”可清除。

程序每天每个关键词取一页、最多 25 条，默认 6 个中英文关键词。成功搜索按北京时间日期缓存；当天相同关键词重复更新会复用结果。更改关键词会发起新请求，可能增加配额使用。Google 的配额以控制台为准，不用旧文章中的额度数字作保证。

官方说明：[项目与 API 启用](https://developers.google.com/youtube/v3/getting-started)、[公开搜索参数](https://developers.google.com/youtube/v3/docs/search/list)。

## 二、免费本地模型

这一项需要安装软件并下载模型。模型尚未安装时不要在页面勾选启用。建议先用小模型评估整理质量，再考虑更大的模型；运行速度需要实际测试。

1. 从 [Ollama 官方 Windows 下载页](https://ollama.com/download/windows) 下载并安装。官方文档要求 Windows 10 22H2 或更新版本，以及符合要求的显卡驱动。
2. 启动 Ollama。安装包和模型会占用数 GB，默认装在用户目录；若 C 盘空间少，安装时可以用 `OllamaSetup.exe /DIR="D:\Apps\Ollama"` 更换安装目录。模型目录可在**用户环境变量**中设置 `OLLAMA_MODELS=D:\OllamaModels`，随后重启 Ollama。不要更改系统范围的环境变量。
3. 打开 PowerShell，执行：

   ```powershell
   ollama pull qwen3:4b
   ```

   这会联网下载 [Qwen3 4B 模型](https://ollama.com/library/qwen3:4b)。本应用不会自己下载安装或拉取模型。

4. 回到 **01 → 信息源与设置 → 免费本地模型**，点“检测本地服务”。应显示已连接，并列出 `qwen3:4b`。
5. 模型名填 `qwen3:4b`，勾选启用，保存，然后更新日报。服务固定连接本机 `127.0.0.1:11434`；拒绝已知云模型别名和返回远程主机的模型。
6. 自动整理有原文输入的个人博客；每张卡标记“模型整理 · 待人工核对”。视频搜索只返回标题和简介，**不会自动获得字幕**。到“发现候选”点“补原文 / 整理观点”，核对本人原作、填写实际提出者、粘贴字幕，再点“用本地模型整理”。阅读结果后保存确认。

官方说明：[Windows 要求、安装和模型目录](https://docs.ollama.com/windows)、[本地 chat API](https://docs.ollama.com/api/chat)。

## 三、先用一张卡评估效果

按下面六项判断是否值得保留：谁提出、核心观点、有什么新意、依据或实践经历、原始时间与链接、可以怎样验证或使用。

- “新意”应解释与哪种常见说法不同，不能只写“很新颖”。
- “依据”应区分个人经历、实验数据、引用他人和未经证实的推断。
- “验证或使用”是建议，不冒充作者已完成的实验。
- 支持观点的引文须在输入原文中原样出现。程序检查引文存在，但不能自动证明观点成立或保证模型概括无误。
- 不想再看某位作者，点“屏蔽作者”；在设置里可以恢复。

抖音、B站、小红书当前只支持手动原作链接与字幕。后续接入要先验证公开、稳定、允许使用的数据渠道；不会绕过登录、验证码或访问限制。
